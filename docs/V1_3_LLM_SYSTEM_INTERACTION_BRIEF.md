- 状态：首个切片已实现，待发布

- 目标演示：Demo 07 / LLM System Boundary Lab

## 用户问题

学习者容易把大模型、上下文、检索、记忆、工具和评估混成一个“AI”能力，也容易认为组件越多，系统就一定越完整。本切片回答：

> 同一个 Base Model 面对不同任务，为什么需要不同的外部系统路径？

## 核心直觉

模型只是系统中的生成组件。系统先识别任务缺少的是当前证据、历史状态还是外部动作，再选择相应边界：

1. `Context` 是当前请求的有限工作区，不会因为加入材料就实时改写模型参数。
2. `Retrieval` 负责取回外部证据，不能单独保证证据被正确使用。
3. `Memory` 是应用选择、保存和恢复的外部状态，不等于模型权重中的私人记忆。
4. `Tools` 承担外部副作用，模型输出只是动作建议，权限和参数校验必须独立存在。
5. `Eval` 在交付前核对证据、约束或工具回执，但一次通过不代表系统永远正确。

三分钟完成标准：学习者能解释为什么“最新政策问答”不需要工具，而“继续并提交报销”不需要知识检索，并能说出两条路径都不能只靠一次模型生成。

## 固定教学场景

| 场景           | 用户请求                                       | 需要的路径                                              | 明确不需要    |
| -------------- | ---------------------------------------------- | ------------------------------------------------------- | ------------- |
| 最新政策问答   | 根据本周更新的内部政策回答陪产假天数并引用依据 | Task → Retrieval → Context → Model → Eval → Result      | Memory、Tools |
| 继续并提交任务 | 恢复昨天已确认的差旅报销并提交                 | Task → Memory → Context → Model → Tools → Eval → Result | Retrieval     |

每个场景固定六步。第二步先展示“只调用模型”的证据或状态缺口，再逐步补上当前任务真正需要的外部组件。切换场景时回到第一步，避免把两条路径的状态混合。

## 范围与非范围

范围：

- 两个双语、脚本化任务对照。
- 模型参数、当前上下文、外部证据、持久状态、工具动作和结果验证的职责边界。
- 与步骤同步的 SVG 节点、路径、状态提示和简化说明。
- 可下载的第十组 SVG/PNG 图源与桌面、移动端视觉证据。

非范围：

- 不调用真实模型、检索库、数据库、记忆服务、工具 API 或评估服务。
- 不实现编排引擎、权限系统、向量检索、长期记忆策略或评估平台。
- 不声称每个真实产品都必须包含图中的全部组件，组件可以合并、拆分或省略。
- 不把脚本化的成功结果写成真实系统可靠性证明。

## 来源与事实边界

### 语言模型参数与上下文

- 来源：[Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)
- 用途：支持“预训练模型可以从自然语言指令和上下文示例生成任务输出”的历史位置。
- 边界：论文不支持模型自动拥有当前私有政策、用户任务状态或业务系统权限，因此演示把这些职责明确放在模型之外。

### 检索增强生成

- 来源：[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)
- 用途：支持参数化生成模型与外部非参数记忆组合、把召回材料用于生成的系统结构。
- 边界：检索不是查询时重训模型，也不保证召回材料相关、引用匹配或最终答案正确。

### 推理、动作与观察

- 来源：[ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629)
- 用途：支持模型生成动作、环境返回观察、后续步骤根据观察继续的交错结构。
- 边界：论文中的任务和环境不等于本演示的报销系统；真实写操作仍需要独立的鉴权、参数校验和回执检查。

### 生成式 AI 风险管理与评估

- 来源：[NIST AI 600-1: Generative Artificial Intelligence Profile](https://doi.org/10.6028/NIST.AI.600-1)
- 用途：支持在生成式 AI 生命周期中记录、测量和管理风险，并持续评估系统结果。
- 边界：该 Profile 是自愿性风险管理框架，不是具体产品的认证，也不证明一次评估可以覆盖全部失败模式。

## 可测试验收标准

- 中英文路由使用相同拓扑，并提供完整的标题、步骤、简化说明和参考资料。
- 两个场景各有六步，切换场景后回到第一步；上一页和下一页控件正确响应。
- 当前节点、累计路径、发现状态和文字解释同步变化。
- 场景按钮可由键盘操作，触控高度不低于 44px，状态通过 `aria-pressed` 暴露。
- SVG 在 fit/detail 模式下可读；390px 页面无横向溢出。
- 数据契约验证节点、边、步骤和场景引用，浏览器测试覆盖中英文与移动端路径。
- 图源 manifest、SVG 稳定 id、PNG 预览和两张发布截图均可重新生成。
- `pnpm format:check`、`pnpm validate:data`、`pnpm lint`、`pnpm build` 与 `pnpm test` 全部通过。
