# v1.6 Guided Causal Learning Brief

- 状态：方案草案，评审中；实现未开始
- 日期：2026-08-02
- 基线：`main` @ `fc41d8b`（v1.5，已完成并发布）
- 范围：P0 v1.5 发布记录收口、P1 故事发现与上下文往返、P2 两条新增策展路径、P3 v1.6 发布收口
- 决策性质：基于现有课程结构、来源覆盖和首条因果故事的教学缺口，不声称由真实使用指标驱动

## 1. 决策摘要

v1.5 已形成 13 章、12 个交互 Demo、27 个来源事件、12 组图源和一条
`feedback-learning` 策展故事。时间线和谱系已经支持可分享筛选与故事深链，但学习者仍需先发现并理解筛选器，才能进入唯一的引导路径；章节末尾也没有直接返回本章历史与谱系语境的入口。

v1.6 聚焦一个用户问题：

> 学习者如何不先掌握整套筛选器，就能从一个问题出发，沿跨时代路径理解一项技术继承了什么、解决了什么、仍缺什么，并随时回到对应章节、时间线和技术谱系？

本版不再增加单点 Demo，而是让现有因果故事可发现、让章节与历史语境可往返，并在现有 27 个事件上增加两条人工审核的策展路径。目标表面保持 13 章、12 个 Demo、27 个事件和 12 组图源，只把故事数量从 1 条扩展为 3 条。

完成后，学习者应能够：

1. 从首页直接选择一条引导故事，而不必先进入时间线筛选器；
2. 沿每一步的“继承 / 解决 / 尚缺”说明理解跨时代变化；
3. 在故事、时间线、谱系和章节之间往返，并保留语言与有效 URL 状态；
4. 明确知道故事是策展式教学路径，不是唯一、完整或自动推断的历史因果链。

## 2. 当前基线与缺口

| 现状           | 已有能力                                                   | 仍存在的学习障碍                                                            |
| -------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| 首页           | 续学入口与 13 章线性主线                                   | 没有 Guided Stories 入口，学习者只能按章节顺序或自行浏览总览页面            |
| 时间线         | 27 个来源事件、章节/谱系筛选和 story 深链                  | 故事入口位于筛选下拉框内，首访用户不容易发现                                |
| 技术谱系       | 节点聚焦、关联事件、章节与时间线往返                       | story 同样依赖控件发现，缺少首页级入口                                      |
| 章节           | 注册表已有 `timelineId` 与 `lineageNodeId`，并有前后章导航 | 章节末尾未使用这些关联提供历史与谱系上下文链接                              |
| Story manifest | 稳定 id、双语文案、有序步骤、行动与返回链接                | 当前只有 `feedback-learning` 一条，测试与 production smoke 仍有单故事硬编码 |

## 4. P1：故事发现与上下文往返

### 4.1 首页 Guided Stories

在首页学习进度之后、完整章节列表之前增加双语 Guided Stories 区域。区域必须直接从 story manifest 派生，不维护第二份故事顺序或文案。

每张故事卡展示：

- 标题；
- 核心问题；
- 步骤数量；
- 进入已筛选时间线的主操作；
- 进入已聚焦谱系的次操作。

故事卡不展示“推荐算法”“完成率”或个性化排序。首版顺序由人工审核的 manifest 决定，中文与英文使用相同拓扑。

### 4.2 章节上下文链接

除 Chapter 00 / Overview 外，每个章节在收尾区域增加两个由章节注册表派生的上下文入口：

- `timelineId` 存在时，进入 `?chapter=<chapterId>#timeline-milestones`；这里的
  `timelineId` 用于证明章节已接入时间线语境，筛选参数仍按现有控制器合同使用
  `chapterId`；
- `lineageNodeId` 存在时，进入 `?lineage=<lineageNodeId>#node-<lineageNodeId>`。

入口必须保留当前 locale。注册表没有关联对象时省略链接，不增加手写 fallback 映射。

### 4.3 URL、筛选与回退合同

- 时间线故事使用 `?story=<storyId>#story-<storyId>`；
- 谱系故事使用同一 `story` 参数和 fragment 约定；
- 选择 story 时清除冲突的 chapter / lineage 筛选，主动选择直接筛选时清除 story；
- 语言切换保留有效 query 与 fragment；
- 非法 story、chapter 或 lineage id 安全清理并恢复完整视图；
- 故事模式只降低非故事内容的视觉优先级，不删除事件、节点、来源或章节链接；
- 无 JavaScript 时仍渲染完整历史、来源、故事说明和章节入口。

首页章节主线使用语义更清楚的 `#learning-path` 锚点；旧 `#mvp` 保留兼容入口，不让已有外链失效。

## 5. P2：两条新增策展故事

两条新故事只复用现有事件、章节、谱系节点和来源模型。新增的是经过审核的连接性说明，不是新的历史事件，也不是自动因果推断。每一步的“继承”表示它承接的更广技术问题、方法背景或基础设施，不表示该事件由故事中紧邻的上一事件直接演化而来。

### 5.1 `rules-to-representations`

- 中文标题：从规则到可学习表示
- 英文标题：From Rules To Learned Representations
- 核心问题：当搜索、规则、不确定性建模和手工特征各自遇到限制时，AI 如何逐步转向数据驱动与可学习表示？

候选顺序：

| 顺序 | 事件 id                      | 本步骤在故事中的作用                                           |
| ---- | ---------------------------- | -------------------------------------------------------------- |
| 1    | `astar-formalized`           | 建立可解释的启发式搜索与明确代价，但表示和启发式仍主要由人设计 |
| 2    | `mycin-consultation`         | 展示领域规则可以组织专家知识，也暴露知识获取、维护和适用边界   |
| 3    | `bayesian-networks`          | 用图结构表达不确定关系，不把所有知识压成确定规则               |
| 4    | `support-vector-networks`    | 让分类边界从样本中学习，但效果仍依赖合适表示与核函数           |
| 5    | `lenet-document-recognition` | 让卷积网络学习局部视觉特征并进入真实文档识别流程               |
| 6    | `imagenet-dataset`           | 把大规模标注数据变成共享训练与比较基础                         |
| 7    | `alexnet-gpu-scale`          | 展示深层 CNN、ImageNet 数据与 GPU 计算共同推动视觉突破         |

策展边界：这是一组互相交叠的研究路线，不是“后一种方法依次淘汰前一种方法”的单线历史。ImageNet 与 AlexNet 的连接必须同时承认算法、数据、计算和工程实现，不把突破归因于单一因素。

### 5.2 `scaled-models-to-reliable-systems`

- 中文标题：从规模化模型到可靠系统
- 英文标题：From Scaled Models To Reliable Systems
- 核心问题：规模化语言模型进入具体应用时，为什么还可能需要外部知识、后训练、行动循环和持续风险评估？

候选顺序：

| 顺序 | 事件 id                       | 本步骤在故事中的作用                                                     |
| ---- | ----------------------------- | ------------------------------------------------------------------------ |
| 1    | `transformer`                 | 用 Attention 重组序列建模主干，为后续规模化语言模型提供架构基础          |
| 2    | `language-model-scaling-laws` | 量化研究范围内模型、数据、计算与训练损失的尺度关系                       |
| 3    | `gpt3-few-shot`               | 展示规模化语言模型可从文本上下文适应任务，但不等于实时学习或可靠事实更新 |
| 4    | `rag`                         | 把可检索外部证据接入生成流程，同时保留“检索不保证正确使用”的边界         |
| 5    | `instructgpt-human-feedback`  | 用示范、排序和反馈优化塑造助手行为，但偏好不等于普遍真理或完整安全       |
| 6    | `react-agent-loop`            | 让推理、行动与环境 observation 交错，运行时修正不等于权重在线更新        |
| 7    | `nist-generative-ai-profile`  | 把生成式 AI 风险纳入持续治理框架，但框架本身不是产品安全认证             |

策展边界：Scaling Laws 描述的训练损失关系不自动推出事实性、安全或产品价值；RAG、偏好后训练、Agent 循环和风险框架分别解决不同系统边界，不能被写成一条保证可靠性的流水线。

### 5.3 内容与来源门

复用现有 event source 不代表新的连接性叙述自动成立。进入实现前必须逐步重读原始来源，并为每一步完成中英文“继承 / 解决 / 尚缺”说明审查：

- 页面声明只覆盖来源支持的历史事实与实验范围；
- 若来源不足以支撑连接性措辞，优先收缩声明或移除步骤，不增加二手推断；移除后仍
  须保持 5–7 步，并在实现 PR 中更新经评审的最终拓扑；
- “继承”可以指向多条先前研究传统或共同基础，不得默认解释为相邻两步之间的直接
  血缘或替代关系；
- 同一故事的中英文事件顺序、关联章节和谱系节点完全一致；
- 所有故事持续展示“策展、非唯一、非完整、非因果证明”的简化说明。

## 6. 数据与实现合同

- 继续使用现有 typed `CausalStory` manifest，不新增 CMS、故事编辑器或通用自动 builder；
- 首页、时间线和谱系统一从 `getCausalStories(locale)` 读取故事，不复制 id、顺序或文案；
- 每条故事拥有稳定且唯一的 id、5–7 个有序步骤、至少一个章节行动、时间线与谱系返回链接；
- 每一步引用存在的 event、chapter 与 lineage node，关联完整性由数据单元测试校验；
- 在增加第二条故事前，调整 localized copy 类型，使每条故事只要求自身的 step、action
  与 return-link id，不被全局 step id 联合类型要求填入其他故事的文案；
- P1 先把现有只针对 `feedback-learning` 的浏览器与 URL 状态断言改为遍历已注册
  story id；production smoke 同样按 story manifest 覆盖全部故事；
- 三条路径稳定运行后，才评估是否存在值得抽取的共享编辑或展示原语；本版不提前抽象。

## 8. 可测试验收标准

- 发布表面恰好包含 3 条双语故事：现有 `feedback-learning` 与两条新增路径；
- 两条新增故事各有 5–7 步，所有故事均包含核心问题、策展边界、行动入口和“继承 / 解决 / 尚缺”说明；
- 13 章、12 个 Demo、27 个事件和 12 组图源保持不变；
- story、step、action 和 return-link id 唯一，所有 event、chapter、lineage 引用可解析且事件来源非空；
- 首页完全由 manifest 渲染，不维护第二份故事顺序；
- `#learning-path` 指向完整章节主线，旧 `#mvp` 仍能定位到同一区域；
- 所有非 Overview 章节都能进入本章筛选后的时间线与谱系，并保持 locale、query 与 fragment；
- story 深链可刷新、可跨语言切换、可清除；冲突筛选互斥，非法 id 安全回退；
- 非故事事件和节点始终可访问，只降噪不删除；
- 无 JavaScript 时仍能访问完整事件、来源、故事说明和章节链接；
- 中文与英文在 375px、390px 和 768px 下无横向溢出，交互目标不低于 44px；
- 故事控件与行动支持键盘、明确焦点和状态播报，reduced-motion 下无依赖动画的状态变化；
- 英文页面正文、控件标签和可访问属性不混入汉字；
- 浏览器测试遍历全部 story id，不为每条故事复制整套领域 spec；
- production smoke 覆盖所有已注册故事，并继续证明 CSP `connect-src 'none'`、无 Cloudflare Analytics / RUM 和无失败请求。

每个实现 PR 至少运行：

    pnpm format:check
    pnpm validate:data
    pnpm lint
    pnpm build
    pnpm test
    git diff --check

若图源或渲染脚本没有变化，不要求为了本版制造新的图源资产；现有 `pnpm render:diagrams` 必须保持可运行且不产生意外差异。

## 9. 风险与控制

| 风险                                 | 控制                                                                            |
| ------------------------------------ | ------------------------------------------------------------------------------- |
| 把策展顺序误读为唯一因果链           | 每条故事固定展示非唯一、非完整、非因果证明说明；其他历史内容只降噪不删除        |
| 复用事件来源后写出来源未支持的新连接 | 对“继承 / 解决 / 尚缺”逐步重审原始来源，证据不足时收缩文案                      |
| 首页增加入口后压过续学主操作         | Guided Stories 位于学习进度之后，保持“继续学习”为首要动作，并验证移动端信息层级 |
| story 与直接筛选叠加后语义不明       | 沿用互斥状态合同，并测试刷新、语言切换、非法参数和返回链接                      |
| 单故事硬编码阻碍扩展                 | 数据、浏览器与 smoke 测试遍历 manifest，不复制平行 id 列表                      |
| “Learning” 被误写成已验证学习效果    | 明确本版是教学导航改进，不引用 CI、smoke 或开发者行为证明学习成效               |
| 借本版恢复联网采集                   | collection mode、CSP、公开隐私说明和 provider 状态保持不变                      |

## 11. 独立后续候选

以下方向保留价值，但必须另建 brief、基线和验收门，不属于 v1.6：

1. **本地复习闭环：** 使用已有自测记录生成待复习清单，并先拆分“完成、继续、核心交互”的产品与事件语义；

5. **新的历史分支：** 生成模型、Diffusion 或多模态等内容扩展必须先证明其用户问题与来源范围，不因热点直接增加 Demo。
